In this kata, the goal is to create a program that simulates the process of gathering gold from a mine and transporting it to a base.</p><p>The Workers are assigned to the gold mine and will automatically begin to gather gold from the mine. Once a Worker has collected a certain amount of gold, it will return to the base to deposit the gold at the Town Hall building.</p><h2 id="input">Input</h2><ul><li>The parameter <code>path</code> represents the initial state of the mining field. It has a mine at index 0, represented by the letter <code>"M"</code>, and a base at index 4, represented by the letter <code>"B"</code>. The worker is initially positioned at index 2, which is a location between the mine and the base.<br></li><li>The parameter <code>time</code> is the number of iterations or ticks that the simulation should run. The method takes the input string, which represents the initial state of the simulation, and simulates the movement of workers for <code>times</code> iterations. The resulting state of the simulation is then converted into a list of strings, where each string represents a row of the grid.</li></ul><pre>MiningRepresentation.generate("M..&lt;B", 9);</pre><h2 id="output">Output</h2><p>The output is a list or an array of strings representing the state of the map after each tick of time until time is over.</p><pre>M..&lt;B // Worker goes to the mineM.&lt;.BM&lt;..B*...B // Worker is mining goldM&gt;..BM.&gt;.BM..&gt;BM...* // Worker brought the goldM..&lt;B </pre><h2 id="explanation">Explanation:</h2><ul><li><code>M</code> - Mine (location to gather gold) </li><li><code>B</code> - Base (location to bring gold) </li><li><code>&lt;</code> or <code>&gt;</code> direction where workers go (left/right)</li><li><code>*</code> - marks that Mine or Base is already busy by other worker</li><li><code>#</code> - marks collision (two workers at the same tile) <br> Note: Mine and Base cannot contain more than one worker at a time </li><li><code>.</code> - Empty tile used to represent road between mine and base</li></ul><h3 id="example-colisions">Example colisions</h3><ul><li><p>Smooth Colision </p><pre>"M&gt;....&lt;B""M.&gt;..&lt;.B""M..&gt;&lt;..B" // smooth collision"M..&lt;&gt;..B""M.&lt;..&gt;.B"</pre></li><li><p>Colision on same tile</p><pre>"M&gt;...&lt;B""M.&gt;.&lt;.B""M..#..B" // two workers on same tile"M.&lt;.&gt;.B""M&lt;...&gt;B"</pre></li></ul><h2 id="tips">Tips:</h2><ul><li>Mine will be always at index <code>0</code>, and Base at <code>last</code> index.</li><li>Workers always spends one <code>tick/time</code> at base, in mine, or traveling one cell.</li><li>There will be no test where workers spawn in collision, base or mine.Currently there is no chance to get a random input that will have <code>#</code> or <code>*</code> in it. But the principle is very simple.<ul><li>Character <code>#</code> means that two workers are on same tile, and one goes to right and other to left(opposite dirrection).</li><li>Character <code>*</code> means that the worker already arrived at one of the destionation so he will go to other one(mine to base or vice versa).</li></ul></li></ul><p>I'm still thinking if I should add more complex random tests that place workers anywhere at the start.
